# Navicat 完整对齐矩阵

记录日期：2026-11-10，Asia/Shanghai。目标是 **1:1 Navicat UI + 完整数据库工具功能 + Windows/Linux/macOS 三平台可用**，基准为本机 Navicat Premium 16.1.1 build 51。现有 OpenNavicat 是部分原型，本矩阵不把核心工作流或现有测试范围当作目标上限。

## 范围、状态与证据规则

**排除**：Navicat 产品账号、产品登录/注册、头像、激活、订阅/商业授权、Navicat 云账号及依赖这些账号的团队协作系统。

**保留**：数据库认证、数据库用户/角色/登录/权限、云端数据库连接及别名、本地查询/模型/任务/图表/备份管理。数据库登录不是产品账号登录。应用及依赖的开源许可证声明仍是正常分发文件，不是待重建的商业授权系统。

参考支持的云数据库认证仍属于数据库功能。1:1 对照允许移除上述排除区域，但不能借此改造保留工具的布局、入口或工作流。

状态描述当前实现，最终对齐验收另外记录：

- **✓ 已核实**：一个明确边界的实现或范围事实有源码/测试/运行证据；不表示完整工具或 1:1 UI 通过。末节列出现有基础。
- **◐ 部分**：存在部分行为，仍缺参考选项、工作流、驱动覆盖或实际对照。
- **✗ 缺失**：当前没有对应实现，或当前自定义 UI 尚未还原相应参考界面。
- **未确定**：参考行为/适用性尚未观察，必须继续调查；不能据此删去功能。

**本轮基线没有任何完整工具或 1:1 UI 门禁获得最终通过。** 每个门禁必须有实际参考行为、OpenNavicat 对应行为和验收结果。新发现的适用功能必须扩展本表。静态文本、截图、按钮、通用 SQL 能力、内部测试或打包成功不能单独关闭完整功能门禁。

## 所有门禁共同的验收协议

1. 在参考应用使用本任务创建的临时 SQLite 文件或一次性服务，记录完整入口、选项、默认值、启用/禁用条件及成功/错误/取消/重启状态；不读取已有用户配置或秘密。
2. OpenNavicat 使用相同 fixture 和步骤，对照同 OS、语言、尺寸、缩放、主题和状态的图像、文字、几何与交互。UI 和工具语义分别验收。
3. 数据库变更通过独立连接或原生工具检查 schema、数据、约束、权限及副作用；文件输出由独立解析器/工具检查并重新导入。
4. 覆盖无效输入、权限不足、断线、取消、部分失败、并发变化及重启恢复；事务/回滚按参考实际语义验证，“没有崩溃”不等于正确。
5. 在三个 OS 的实际打包程序重复适用 case，记录平台/驱动版本、reference 证据、fixture、结果和剩余限制。只有参考及版本证据可标记“不适用”。

各表“关闭门禁所需验收”均包含以上五步，列中进一步指定必须观察的结果。完成记录应为每个 ID 增加截图/步骤、测试结果和三平台验收链接。
