# OpenNavicat v0.8.0

本里程碑加入 Linux Navicat 历史连接发现、MongoDB 六页索引设计器，以及随安装包提供的原生 JavaScript 查询引擎。
完整 Navicat 数据库工具和 1:1 界面仍在实现，保留所有未完成门禁；产品账号、产品登录、激活、订阅和云账号协作继续排除。

## 本次变化

- 普通启动发现 Linux Navicat 18 原生历史连接及分组，显示已识别的七类核心驱动基础配置。
  来源格式依据实际 Linux 18.0.3 的隔离运行观察；所有 Linux 原生候选都需要先复核再手动连接。
  不提取保存的密码，不自动连接；不完整来源保留已有配置和明确有效的分组关系。
  macOS 既有历史加载和 Windows 候选发现继续保留，不能据此声称 Windows 18 最新原生格式已经验收。
- MongoDB 索引列表使用九列实际元数据，支持有序复合键和常规、存储引擎、排序规则、文本、地理空间、脚本预览六页设计。
  接入新建、修改、保存预览、永久删除确认、停止、关闭前保存和断开恢复；同名索引按集合分别定位。
  未知或不能无损表达的 BSON 元数据保留原字节并只读，完整选项与平台对照仍开放。
- 新建 MongoDB 查询默认使用原生 QuickJS-NG 引擎，支持变量、函数、循环、BigInt 和已实现的数据库命令/游标接口。
  父进程持有数据库会话，保留 BSON 类型、只读校验、确认写入和部分/未知结果，并提供有界执行和进程回收。
  这是已实现的 JavaScript 与数据库桥范围，不是完整 mongosh、Node 或 Navicat 全局/API 等价。
  补齐索引预览所用的 BSON 构造形式，可将“执行脚本（集合 UUID）”复制到默认内置 JS 查询并实际运行。
- 草稿、历史、收藏和已确认文件保存执行语言。旧查询继续使用原来的命令/Canonical EJSON 解释方式；
  没有语言记录的 MongoDB 文件要求选择原有语义，避免普通数值在升级后由整数静默变成 Double。
- 修复停止请求延迟后误取消后续 MongoDB 操作、断开过程中继续读取索引信息、过期预览覆盖新草稿、索引控件裁字和损坏语言元数据导致启动失败等问题。
- README 保留一段真实应用 GIF，增加 JavaScript 和索引工作流；连接、数据和图像均在隔离演示环境生成。

## 数据库操作边界

MongoDB 修改索引通常是先删除、再创建，两步不是事务。集合 UUID 保护集合身份，不提供索引定义的原子 CAS。
失败后显示每一步的确认状态及重新读取的实际目录，保留草稿，不自动重试或回滚已完成步骤。
按名称寻址的辅助脚本与实际 UUID 命令分别展示，不能混同它们的保护范围。

现有核心驱动为 SQLite、PostgreSQL、MySQL、MariaDB、SQL Server、Redis 和 MongoDB。
Oracle、Snowflake、全部高级认证/拓扑、向导、模型/BI 和各驱动专属工具，以及三平台完整参考对照仍按总矩阵继续推进。
详见 [完整对齐矩阵](https://github.com/shubolab/opennavicat/blob/main/docs/parity-matrix.md) 和
[0.8 验证记录](https://github.com/shubolab/opennavicat/blob/main/docs/validation-0.8.md)。

## 安装与验证

发布门禁要求六个原生目标各自构建、冻结运行，并实际安装、启动、卸载；独立数据库检查和相应零跳过资格范围也必须成功。
Windows、Linux、macOS 分别提供 amd64 和 arm64 的 EXE、DEB、DMG 安装包，附 `SHA256SUMS` 与 `build-manifests.json`。
JavaScript helper 随包分发，校验实际运行字节、架构与固定来源，不在用户运行查询时下载或编译。

安装包仍为无发布者签名/Apple 公证的早期预发行。Windows ARM64 的安装引导器使用 x86，安装后的应用和原生依赖为 ARM64。
Linux DEB 基于 Ubuntu 24.04，要求 glibc 2.39 或更新，并通过包管理器安装声明的 Qt 图形库与字体。
用户 Dell Windows/RDP 与无桌面 WSL 的后续人工验收按要求延期，原现场保留；托管原生 CI 与该现场验收分开记录。
