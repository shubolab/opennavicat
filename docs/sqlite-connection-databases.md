点击加号打开新增 sheet，不直接添加空行或立即打开文件选择器。外层窗口为 900×700，

## 官方文档补充，独立于本机运行观察

Navicat 18 的 Windows 官方高级连接页还列出 Cipher Name 算法选择，以及加密与密码选项。
这确认需要继续枚举对应入口；该页没有公布具体算法取值、文件格式、codec 版本或附加库
如何继承算法，不能由此认定本机参考采用 SQLCipher 或 SEE。
[官方高级连接说明](https://www.navicat.com/manual/online_manual/en/navicat_18/win_manual/con_adv_settings.html)
不替代 macOS 实际下拉选项、加密文件和三平台运行验收。

标准 SQLite 对未知 PRAGMA 不报错而直接忽略，因此仅执行 `PRAGMA key` 无错误不能证明
加密生效。必须使用实际加密 fixture、错误密码、独立兼容读取及原生 provider 检查。
[SQLite PRAGMA 文档](https://www.sqlite.org/pragma.html)

## 实现与验收合同

- UI 保留三列、裸加减、sheet 新增/编辑、取消隔离、整行选择和是/否文字。草稿稳定行 ID
  与有序元数据、密码分别持有；不能把秘密放入表格、tooltip、repr 或 workspace JSON。
- GUI 只捕获普通配置快照，实际打开和 ATTACH 经串行 worker。文件值绑定，别名按 SQLite
  规则引用；全部附加成功及目录验证之后才发布 session，任一失败完整关闭临时连接。
- 主库的已有/新建意图、附加库是否允许创建及只读语义分别核实；不得因检查/打开竞态
  意外新建文件。加密标记不能被忽略，未确认兼容的 engine 不能用空操作 PRAGMA 冒充支持。
- Store 需要显式嵌套元数据 codec、secret 版本/清理和失败补偿。现有四个顶层秘密的清空
  不能保护新嵌套密码；当前 SQLite 主密码保存开关不能代替未观察的附加密码保存策略。
- 比较预览需绑定实际 alias→文件及 session generation，换配置或换文件后拒绝旧预览。
  备份必须针对选中的 schema，不把附加库操作悄悄导向 main；设计器、网格、导入导出和
  断开/重连都要用真实附加库检查。

单个普通 ATTACH 与同进程保存重开已取得上述有限运行观察；进程重启、密码记忆、
加密格式与 engine、无效/重复/保留别名和路径校验仍待观察。文件列双击、排序、多选/批量删除、键盘、重排、只读、并发变化和三平台
主题/DPI/焦点/禁用状态也未验收。UI、工具功能、原生安装与三平台参考分别保留门禁，
本页不关闭 U08、U15、C01 或完整 goal。
