# SQLite 全新未保存草稿：常规与高级默认控件

2026-11-14，macOS，Navicat Premium 18.0.5 build 321，执行文件 SHA256
`3857a354fde7f42f8afbf9ef3a25956e6ff3b9745f598f77bbab1d27e7493bd1`。
此前加密互读复用了有历史口令的同一生成 profile，不能据此推出新草稿默认值。本次在参考
正常退出后重新启动，从新建连接选择器进入一个全新、未保存、未命名的 SQLite 草稿。
这仍是本机现有偏好环境下的新草稿，不是清空用户配置后的 factory-default 证明。

既有动作摘要只保留开关和十五项候选，没有记录空 cipher 值，故进行了这次有界观察。
Computer Use 逐步读取真实 AX 与完整画面；没有新 REA UI Evidence ID，也不套用静态 ID。

## 空白 Cipher 的有界 Test

随后增加独立控制：新进程进入全新、未命名、未保存的 SQLite 草稿，选择现有数据库，
勾选加密，两处保存密码均关闭；Cipher 从未输入、展开或选择，测试前后 AX 均为空白。
只使用本轮 provider 生成文件的 0400 副本，Settings 指向独立临时目录。每次 Test 都另弹
数据库加密密码提示，输入同一生成口令后得到下列真实结果；口令本身没有写入文档或收据。

| 已知加密文件 | 空白 Cipher 的实际 Test 结果 |
| --- | --- |
| aes256cbc | 失败：`26 - file is not a database` |
| chacha20 | 失败：`26 - file is not a database` |
| aes128cbc | 成功：服务器版本 `3.45.0` |

前两例使用同一未保存草稿切换路径；取消并正常退出后，第三例在另一次新进程、全新
草稿中执行。没有按好或保存 profile，没有执行 SQL，也没有创建数据库。该结果证明
本机空值路径可连接本轮 AES128 文件、不能连接本轮 AES256 和 ChaCha20 文件；它支持
重建时将空值按 AES128 兼容处理这一推断，但不证明参考的内部算法赋值、任意文件自动
探测、其它 cipher、创建模式或其它平台的行为。成功 Test 也不替代实际行读取验收。

三份副本与三个对应 provider 原件的测试前后 SHA256、字节数均一致，无 sidecar。
两个 Settings 目录均保持空，按精确白名单清理了三份副本和两处临时目录；provider 原件
保留，参考执行文件哈希未变，正常 Quit 后只读应用清单确认未运行。私有控制收据在
本工作树忽略的 `artifacts/sqlite-blank-cipher-10h/`，没有提交原始参考画面或私人路径。
