# Navicat 18 MongoDB 实际界面与行为观察

日期：2026-11-10。参考为用户指定的 Navicat Premium **18.0.5 build 321**。
本稿只记录本任务的隔离 MongoDB 样例库与合成数据，不公开原版现有连接树截图、真实连接名、
主机、凭据或业务数据。界面动作通过 CUA 执行；下列 `M18-*` 是本文观察编号，不是 REA Evidence ID。
静态资源声明另见 [18 版静态记录](reference-18-static.md)，不能替代本稿的实际执行结果。

当前参考连接为任务自建的 `OpenNavicat MongoDB UI Reference`，样例库为 `opennavicat_fixture`。
这是本机 loopback 的 disposable fixture，不是用户业务库。既有样例与容器由数据库实现代理管理，
本轮不删除或清空对方数据。原始诊断和补充回执保留于 Git 忽略的 `artifacts/`。

## M18-01：主工具栏与导航分类

实际选中 MongoDB 连接后的主工具栏，从左到右为：

`连接 → 新建查询 → 集合 → 视图 → 函数 → 用户 → 其它 → 管道 → 查询 → 自动运行 → 模型 → BI`。

选中索引时，“其它”会显示当前类别“索引”，AX Help 仍为“其它”。右侧另外有信息窗格与 AI 会话面板切换。
本条只证明入口和顺序，不证明数据库用户、自动运行、模型、BI 或 AI 的完整 MongoDB 行为已执行。

打开样例数据库后的导航分类顺序为：

`集合 → 视图 → 函数 → 索引 → MapReduce → 聚合管道 → GridFS 存储桶 → 查询`。

`documents`、`measurements` 位于集合对象列表；`files` 位于 GridFS 存储桶。
MapReduce 和聚合管道是独立分类，不应合并成通用 SQL 查询分类。

## M18-04：原生聚合查询与结果区

在现有的自有样例查询标签重新点击“运行”，实际执行：

```javascript
db.getCollection("documents").aggregate([
  { $group: { _id: "$status", count: { $sum: 1 } } }
])
```

本轮 fresh 执行返回四个结果文档，列为 `_id`、`count`，各组计数为 1。
这与前轮保留的三个结果不同，因为自有样例后来新增一条；先前标签结果不能视作最新服务状态。
没有执行写入 stage。

查询工具条实际包括保存、查找创建工具、聚合创建工具、美化脚本、代码段、询问 AI、
在编辑器下方/旁边显示结果、专注模式，连接与数据库选择，以及运行、解释。
脚本区 AX 仍标“SQL 编辑器”，其内容实际为 MongoDB JavaScript/mongosh 风格调用。
结果区为消息、摘要、结果 1；提供固定、单元格编辑器、类型颜色、导出结果，数据/信息切换，
网格/树/JSON 视图、分页和设置。以上入口并不证明支持任意 JavaScript 执行或全部 shell API。

## M18-05：find、排序、限制与 BSON 显示

本轮新建独立查询标签，实际执行以下只读语句：

```javascript
db.getCollection("documents")
  .find({}, { name: 1, quantity: 1, status: 1 })
  .sort({ quantity: -1 })
  .limit(2)
```

实际返回两个文档，`quantity` 按 3、2 排序；投影仍默认保留 `_id`。
切换结果的 JSON 视图后，内容使用 `// 1`、`// 2` 分隔文档，保留
`ObjectId("…")` 与 `Int32("3")` 等 mongosh 构造形式，不是严格 JSON 或 canonical Extended JSON。
本轮查询标签通过 `Cmd+W` 关闭，在“保存 / 不保存 / 取消”确认中选择不保存；没有保存查询文件。

## M18-06：GridFS 列表、筛选、预览与传输

`GridFS 存储桶 → files` 实际打开独立主工作区标签，标题带 `- GridFS`。
文件工具条包含打开文件、删除文件、上传文件、下载文件、筛选、预览、进度、专注模式。
初轮曾在无选中项时只记录到部分按钮；M18-09 在已有标签中仍看到完整工具条，不能把“选择后才出现”当成所有状态的通用规则。
文件列表显示名称、ID、长度、数据块大小、上传日期、MD5、内容类型、别名、元数据，底部有分页和设置。
全局右侧信息窗格仍是独立区域，没有并入 GridFS 文件预览。

原样例 `hello.txt` 由实现代理先前创建，长度 18 bytes。
本轮点击“预览”后实际提示 **“‘预览’仅支持小于 1 MB 的图像”**，并提供“保存到磁盘”。
这证明文本文件不在该预览路径中；本轮没有测试精确 1 MB 边界。

筛选按钮展开单独的条件区域，含应用、清除、启用勾选、字段下拉“名称”、运算符“包含”、输入框和加减按钮。
实际应用名称包含 `hello` 返回一个文件；改成自造不存在名称返回零个；点击清除恢复一个文件。

经夹具所有者协调，仅上传一个新生成的 32×24、93 bytes 纯色 PNG：

1. 上传文件打开原生文件选择器；选择本轮唯一合成文件后，列表显示其长度、MD5、`image/png`。
2. 进度区显示该文件 `Done (93 B)`，总计 1、完成 1、失败 0。
3. 选择该文件并点击预览，预览区实际出现图像；在专注模式目视确认合成蓝色色块。
4. 下载文件打开目录选择器，选择隔离下载目录后保留原文件名；进度变为总计 2、完成 2、失败 0。
5. 独立读取源文件与下载文件，93 bytes 逐字节相同，SHA-256 均为
   `2a2581f7959d4a467f8a488bb59ef1b7f44faedd20a165f3c9b04f759f73016f`。
6. 只选择本轮 PNG，点击删除文件，在明确列出该文件名的确认中删除。
   独立 PyMongo 按精确 `_id` 确认对应 `files` 记录与 `chunks` 均已消失，原 `hello.txt` 保留。

本轮没有执行“打开文件”调用外部应用，也没有修改原样例文件的名称、元数据或内容。
没有在文档或应用资产中保存参考程序的连接树截图。
无敏感信息的传输与清理回执为 `artifacts/mongodb/reference-probes/gridfs-roundtrip.json`。

## M18-07：索引对象列表、设计与保存/删除

索引是数据库级独立导航分类。实际对象列表列为名称、索引类型、集合名称、唯一键、背景、稀疏、
在此之后过期（秒）、版本、大小。未选中时提供新建索引、刷新、搜索；选中后提供设计索引与删除索引。
右键菜单为设计索引、新建索引、删除索引、管理组、刷新；管理组内仍有新建组及当前禁用的添加/排除。

双击已有合成索引 `quantity_name` 实际在主工作区打开设计器，没有打开独立顶层对话框。
本轮逐页查看，未改变它的任何选项：

| 设计页 | 实际可见字段或区域 |
| --- | --- |
| 常规 | 集合名称；唯一键、背景、稀疏；在此之后过期（秒）；索引版本；有顺序的字段/类型表；键/部分筛选切换 |
| 存储引擎 | 脚本编辑区；该现有普通索引为空 |
| 排序规则 | 区域设置；大小写级别、大小写优先、强度、数值排序、替代、最大变量、逆向、规范化；当前未选 locale 时其它项禁用 |
| 文本 | 默认语言、语言覆盖、索引版本；字段/权重表及加减按钮 |
| 地理空间 | 2D 位精度、最大、最小；2D 球体索引版本；GeoHaystack 存储桶大小 |
| 脚本预览 | 更改 / DDL 切换；更改显示“无更改”，DDL 使用 createIndex 和 Int32 构造形式 |

已有索引的键顺序是 `quantity DESC, name ASC`。类型下拉实际可见
`ASC / DESC / 2D / 2DSphere / Hashed / Text`。
这些高级选项的出现不证明当前服务版本接受全部选项；本轮未保存文本、地理空间、TTL、排序规则或存储引擎配置。

保存/删除闭环只在新建的唯一临时集合上执行，不在原样例集合上增删索引：

1. 独立 PyMongo 创建两个合成文档的临时集合；原版新建索引草稿指定该集合与 `status ASC`，普通、非 unique、非 sparse、无 TTL。
2. 在脚本预览确认仅有目标集合与目标键，再点击保存。原生确认对话框要求索引名称，显示最终脚本预览，
   另有“不再显示脚本预览”复选框；本轮没有更改该偏好。
3. 填入唯一测试索引名后再次核对脚本并保存，设计页标题更新为新名称，“更改”显示“无更改”。
4. 独立 PyMongo 确认真实索引 `key=[('status', 1)]`、版本 2，未带 unique/sparse/expireAfterSeconds。
5. 关闭本轮保存页，选中唯一测试索引，按 `BackSpace` 出现删除确认。必须先勾选
   “我了解此操作是永久性的且无法撤消”，删除按钮才启用。
6. 删除后导航中该索引消失；独立读取确认临时集合只剩 `_id_`，再按原 UUID 核对并清理自建临时集合。
   原样例文档数与既有索引列表均保持原状。

索引键表格需实际结束单元格编辑后再核脚本；仅设置 AX 显示值不能作为模型已提交的证据。
本轮曾在未结束编辑时看到旧预览，纠正输入并核对脚本后才执行保存，未执行空键或错误集合脚本。
回执为 `artifacts/mongodb/reference-probes/index-probe.json`。本轮自有查询草稿、索引设计页及临时数据库对象均已清理；
实现代理的整个参考容器、既有集合和原文件继续保留。

## M18-08：前轮实现代理的实际观察

以下事实来自数据库实现代理前一轮 CUA 与独立 PyMongo 核验，补充回执为
`artifacts/mongodb/reference-observations.json`；不是本轮观察者重复执行或 root 直接观察的声明：

- 连接常规页有 SRV 开关；连接方式为 Standalone、Shard Cluster、Replica Set。
  认证选项为 None、Password、LDAP、Kerberos、X.509。选择 Password 后有认证数据库、用户名和密码。
  实际自有普通来源保存的非秘密枚举为 Password / admin / Standalone / Primary，retry reads/writes 开启，SRV/SSL/SSH 关闭。
- 集合主工作区默认网格，包含单元格编辑器、筛选/排序、列、历史、折叠、类型颜色、分析、导入导出、生成、脱敏、专注模式；
  底部有增删、刷新、分页，提供 Grid/Tree/JSON 切换。
- BSON 显示还实际出现 Long、ISODate、Decimal128、Binary.createFromBase64 等构造形式。
  插入对话框使用 BSON JavaScript 编辑器，有 Add、Cancel、Validate；自有 `insert_probe` 文档经 Validate 后 Add 成功。
  独立 PyMongo 确认 `Long('9007199254740995')` 实际保存为 `bson.Int64`，整数值精确不变。
- 聚合创建工具是独立模态窗口，有 Pipeline / Script Preview，图为 source/stage/output；选中 stage 后有 operator 下拉与 JS body。
  当时脚本仅有 `$group`，构建器却显示 `$match` 与 `$group`；默认节点或解析原因仍未知，不推断构建器必然插入有效过滤。

只记录自有来源的 enum/布尔/类型结构；完整无秘密合成来源 fixture 为
`artifacts/mongodb/synthetic-native-profile.json`。没有为此读取或公开其它历史连接资料。

## M18-09：冻结前的网格、单文档树与 GridFS 布局复核

2026-11-10 再次实际打开用户指定的 18.0.5 build 321，只操作已核验容器 ID、归属标签及 loopback 映射的自有 MongoDB 样例。

### 集合的模式切换有不同工具条和导航语义

- 网格中仍能看到此前合成的 Decimal128、Long 和 Binary 数值；缺失字段显示 `(N/A)`，BSON null 显示 `(NULL)`，两者有区别。
- 网格工具条有集合配置文件、单元格编辑器、筛选与排序、列、历史、全部折叠、类型颜色、分析、导入、导出、数据生成、数据脱敏、专注模式。
- JSON 模式未出现单元格编辑器、列、全部折叠、类型颜色这四个网格按钮，保留筛选/排序、历史和其它相应工具。
  JSON 正文仍为整页多个文档及 JavaScript/BSON 构造式，不能按当前实现的 Canonical Extended JSON 语言验收。
- **树视图一次显示当前选中的一个文档，不是整页文档的总树。** 从网格中选中的合成 `gamma` 切到树后，只出现该文档的 `_id/name/quantity/optional`。
  点击“第一条记录”后真实切到合成 `alpha`，其 `attributes` 有可展开的嵌套行。
- 树中的字段名和值在 AX 中为 settable 控件，类型为 Object ID、String、Int32、Document、DateTime 等 popup；
  本轮未改变字段名、值或类型，所以不据此声称类型转换及编辑保存已通过。
  其底部按钮语义为第一/上一/下一/最后**记录**，不同于网格的页面导航。

当前 OpenNavicat 0.6 的树是整页多文档的只读 `QTreeWidget`，写入通过独立 Extended JSON 文档编辑器完成。
这是明确的已知差异；不能将类型保持与安全写入证据等同于原版单文档树、行内编辑、类型 popup 或记录导航的 1:1 完成。
网格中缺失/null 的文字、按视图变化的工具条也仍须继续对齐。

## 仍开放的门禁

- 原生任意 JavaScript/mongosh API、完整聚合创建工具编辑和保存、MapReduce、服务端函数。
- 单当前文档 Tree 的行内编辑/类型 popup/记录导航、视图专属工具条、全部 BSON 类型/边界的原版读写、重复字段与原始 BSON 保全。
- 时间序列集合创建和选项、views、集合验证/维护、全部索引高级选项及变更行为。
- GridFS 原版底部预览/进度布局与单位呈现、大文件/多块、失败恢复、取消、重复文件名、元数据修改、外部打开和精确大小边界。
- LDAP/Kerberos/X.509、SRV/replica/sharded、TLS/SSH、read preference、数据库用户/权限的原版完整流程。
- 数据字典、生成/脱敏、备份工具、模型/BI、自动任务以及三个操作系统的真实 UI/行为对齐。

本稿的局部执行不构成完整 MongoDB 功能、BSON 无损编辑、安全连接、权限管理、原版 UI 或跨平台验收。
未执行和无法确定的行为继续保留开放门禁；产品账号/授权/订阅/云团队账号排除规则不改变数据库工具范围。
