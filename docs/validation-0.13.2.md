## 当前接入

成功、复制和关闭使用独立绘制，裸加减与圈加号保持不同语义。共享结果条在 GUI 线程绘制
当前 DPR 的图形，状态、详情按实际字体裁切省略；显示和 tooltip 各限制 512 字符，复制
内容单独限制 1024 字符。长版本文字不会把窗口撑宽。已修复颜色样式导致动态字体继承失效，
普通、失活和禁用文字分别使用对应状态。

SQLite 通过原有串行测试 worker 真实读取 `sqlite_version()`，会话仍由该 worker 关闭；返回
不可变的文字数据，公开 `test_finished(True, "连接成功")` 保持原协议。成功条和 44px 底栏
放在设置列，取消/保存实际按钮位于末端。成功后仅连接线变绿；重测、失败、驱动或连接设置
变化会清除旧反馈。现有 Oracle worker 与独立绘制的连接图不改用 SQLite 状态。

Oracle 数据库页三个文字按钮改为灰色裸加减与刷新图形，保留本地增删回调、配置草稿、
自定义列表开关和未实现的获取功能禁用状态。测试条复用有界绘制；原 Oracle 成功复制内容
仍为 `✓  连接成功  服务器版本: ` 加原先限制的版本文字，视觉上的勾改为图形。

GridFS 条件加减和执行计划详情关闭按钮也替换了字体字形；这是原有控件的可缩放绘制接入，
尚未取得这些具体位置的参考图形验收。详情关闭或切换时清除成员、移出场景并 `deleteLater()`，
旧关闭信号按实际 proxy 身份校验，避免关闭新详情。没有新增数据库行为。

smoke 报告开始由实际 `QApplication.platformName()` 记录 `qt_platform_name`；读取在 GUI
主线程进行。这不回填 0.13.1 报告中未记录的实际平台，也不代表原生人工参考验收。

## 正式 CI 与发布门禁

绑定 `7ab0f58` 的 [CI 43551247449](https://github.com/shubolab/opennavicat/actions/runs/43551247449)
已结束且结论为失败。九项必需任务中六项通过，三项失败：两个 Windows 架构任务均在录制器
子进程测试的 PATH 依赖处失败，Oracle 原生 arm64 任务在 fixture 启动阶段失败，容器进程
退出码为 24。后者未保留足以确定底层根因的原始服务日志，不能据此断言 Oracle 产品行为或
数据库功能已经通过。发布任务已跳过。

本轮实际只有 13 个 artifacts，不满足预期的完整 15 项清单，缺少 Windows amd64 和 arm64
安装器。离线诊断只验证了下载的验证 ZIP 运输信息和 ZIP CRC，没有下载、挂载或核验安装器
字节；通过的部分任务和报告不能替代整轮通过、六安装器及校验和、各目标 smoke 和公开下载
验收。Windows 子进程在首次 Qt 导入后才取 PATH 基线；PySide6 自身的 Windows 加载器会
合法加入其 DLL 路径。相对工具查找与离开 owned CWD 后恢复的断言均保留，并拆开失败
消息。修正后的本机三例通过，新 Windows CI 仍需验证，不能仅凭 macOS 宣称已修复 Windows。

Oracle fixture 现会在连接重试后复核精确 CID、镜像、owner 和挂载，发现 exited/dead 立即
失败，保持 360 秒准备预算；失败日志只在内存按 5 秒/64 KiB 捕获，落盘仅允许最多 32 种
ORA/SP2 代码计数和有限状态。CLI 任意 stderr、环境和端点不写入报告。真实孙进程两例
复现旧 collector 清理不足，再改为持有 leader 身份、清理独立进程组后回收；清理另有
各 1 秒的 reap/组消失窗口。局部严格 192 通过/3 条件跳过；前一 e16 候选的自有原生 ARM
后端 14 项通过但未复现旧 CI 退出 24，不解释其原因，也不冒充最终版本的 Linux CI 资格。
最终整合源及新整轮 CI 仍需取得各自证据，不能回填到旧 CI。
