### 整个工具栏按钮短暂消失

ca4 的实际 Oracle `catalog-table` 画面曾在“其它／用户”位置留下整块空白，连文字也不见。
独立生成的 Oracle fake session 经实际 MainWindow/offscreen 复现：顺序已经正确时，
每次 `refresh_actions()` 仍移除再插入两个 QAction，导致重建的 QToolButton 暂时隐藏、
几何为 `[0,0,100,30]`；8/8 次立即刷新均出现空白，处理后续布局事件才恢复显示。
该重排块在较早 Oracle 集成中已存在。

续作仅在所需前驱不正确时移动动作，顺序正确时保留同一按钮及其可见性、几何。
Oracle／普通 SQL 的“其它、用户”、SQLite 的“用户、其它”与 MongoDB 各自位置、
禁用状态和回调保持原规则。最终相同测试文件字节在旧产品上 16 失败；修后新增 16、
Oracle fake UI 18 和既有图标上下文 5，共 39 通过、零跳过，均使用 warnings-as-errors。
独立立即状态测量为修前 8/8 隐藏、修后 8/8 可见，不依靠新增等待时间掩盖空白。

测试夹具的销毁顺序另行红绿验证：实际 pytest-qt 执行 `close()/deleteLater()` 后，
受控送达 DeferredDelete，旧夹具在 `yield` 后读取 QThreadPool 报“已删除”。将 Qt 读取、
空闲断言和 fake session 摘除移至具名 `before_close_func` 后，同一探针通过；探针仍确认
窗口与线程池原生对象已失效，未以跳过检查或延长生命周期取得通过。该证据与产品重排
修复分开记录。最新真实 Cocoa 的三个 `catalog-table` 阶段均已目视看到完整“其它／用户”，
