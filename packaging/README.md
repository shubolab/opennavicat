# Native installer builds

Build the app on each target OS and CPU, then run:

```sh
python scripts/package-installer.py --output-dir release-assets --verify-installed
```

`--arch amd64` or `--arch arm64` is optional and must match the native host.
The script reads the actual PE, ELF, or Mach-O headers of the executable and
every native image in the bundle. It refuses mismatched native dependencies,
escaping symlinks, and macOS builds running through Rosetta.

The six native release jobs produce these installer families:

| OS | Native architectures | Installer | Install verification |
| --- | --- | --- | --- |
| Windows | amd64, arm64 | Inno Setup `-setup.exe` | Separate per-user verification AppId, temporary installation, real runtime smoke report, uninstall |
| macOS | amd64, arm64 | `.dmg` | Read-only mount, Applications link, isolated app copy, real runtime smoke report, remove and detach |
| Linux | amd64, arm64 | `.deb` | Actual apt/dpkg install, `/opt/opennavicat` executable, launcher and desktop entry, real runtime smoke report, purge |

Windows requires an installed Inno Setup compiler, discoverable as `ISCC.exe`,
or supplied with `--iscc`. An x86 Inno installer wrapper can install an ARM64
application. The application itself must contain native ARM64 PE images, and
the manifest records the wrapper separately. The official
[SetupArchitecture](https://jrsoftware.org/ishelp/topic_setup_setuparchitecture.htm)
and [ArchitecturesAllowed](https://jrsoftware.org/ishelp/topic_setup_architecturesallowed.htm)
documentation describe that distinction.

Linux requires `dpkg-deb` and a native glibc build host. Its runtime baseline is
recorded from that host's glibc version. Installed verification needs a clean
host and root or passwordless CI sudo. It refuses to overwrite an existing
OpenNavicat package, application directory, launcher, or desktop entry.

Every artifact has a SHA-256 sidecar and JSON manifest containing the release
version, OS, native architecture, application binary identities, and actual
verification state. `--verify-installed` requires the installed application to
write a report proving six SQLite result rows, its version and native runtime
architecture, libpq, all four driver imports, SSH crypto, and Qt. An empty or
missing report fails even if a windowed Windows process returns zero.

No publisher signing or Apple notarization credentials are configured here.
The distribution is unsigned for publisher trust; macOS payloads may still
carry the ad-hoc signatures generated by the native bundler.
